Agentic Loop Cheatsheet

Print this one out. It's the shape you'll reach for every time you wire up tool use, on any of your three providers.

The skeleton (pseudocode, provider-agnostic)

messages = [user_message]
for i in range(MAX_ITERATIONS):
    response = call_model(messages, tools=tools)
    if not response.wants_tool_call:
        return response.text          # done — this is the exit

    messages.append(response.raw)     # keep the assistant turn, tool-call and all
    results = [run_tool(call) for call in response.tool_calls]
    messages.append(tool_results_message(results))
    # loop continues — model sees the results next iteration
raise RuntimeError("hit MAX_ITERATIONS — model never stopped calling tools")

Four moving parts, every time: call → check why it stopped → run tools if asked → append results and repeat. Everything below is just how each provider spells those four parts.

The one shape difference that bites people: Anthropic returns all tool results in a single user message with multiple tool_result blocks. OpenAI/Groq want one message per tool call, each with role: "tool". Copy-pasting the Anthropic append logic into your Groq/OpenAI path is the classic first bug.

Non-negotiables

  • Always cap iterations. A model that keeps calling tools forever is not hypothetical — malformed tool results, ambiguous instructions, and buggy tools all trigger it.
  • Always append the full raw assistant turn, not a re-derived version. The API needs the exact tool-call IDs it generated to match your results back up next request.
  • A failed tool is still a result, not a raised exception out of the loop. Catch it, tell the model what went wrong (is_error: true on Anthropic), let it decide what to do next.
