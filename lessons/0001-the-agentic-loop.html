Lesson 0001

The Agentic Loop

Your AnthropicAgent.run() right now does exactly one thing: send a prompt, get one response, return it. This lesson is about the one change that turns that into an agent — and nothing more than that change. No frameworks, no new abstractions.

The definition, from the source

Agents ... are typically just LLMs using tools based on environmental feedback in a loop. It is therefore crucial to design toolsets and their documentation clearly and thoughtfully. Anthropic, Building Effective Agents (Dec 2024)

Unpack that sentence and there are exactly four moving parts:

call model
→
check why it stopped
→
run any tool calls
→
append results
↶

That loop keeps turning until the model stops asking for tools and just answers. That's it — the entire conceptual leap from "single LLM call" to "agent" is looping on tool calls until the model is done. Everything else you'll ever add (retries, budgets, subagents, memory) sits on top of this.

Where your code stands today

Look at app/factory/anthropic.py — run() makes one call to self.client.messages.create(...) and returns the text. There's no check of stop_reason, no branch for "the model wants a tool," no re-call. If you pass tools= today and the model responds with stop_reason == "tool_use", your code silently returns whatever text happened to be in response.content — which is often empty, because the model's whole response was the tool call.

That's the bug this lesson fixes.

Quick recall — stop / finish reasons
